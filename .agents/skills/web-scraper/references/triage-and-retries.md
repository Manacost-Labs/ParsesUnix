# Классификация ответов и ретраи

## Главное правило

Решение о повторе и эскалации принимает одна функция triage. Код конкретного парсера не должен иметь собственный бесконечный `retry` или `except: continue`.

| Вердикт | Пример | Действие | Платная эскалация |
|---|---|---|---|
| `OK` | 2xx, канарейка и схема валидны | сохранить | не нужна |
| `DEAD_URL` | 404/410 цели | карантин и поздняя перепроверка | запрещена |
| `ORIGIN_DOWN` | timeout, DNS, 5xx без WAF-сигнатуры | 5м/30м/2ч тем же бесплатным уровнем | запрещена |
| `RATE_LIMITED` | 429 цели | `Retry-After`, снизить скорость и конкуренцию | запрещена |
| `AUTH_REQUIRED` | 401/402 цели | остановиться, запросить разрешённый способ доступа | запрещена |
| `ACCESS_DENIED` | 403/2xx с сообщением о контроле доступа (login required и т.п.) | проверить права/политику, не обходить контроль доступа | запрещена |
| `BLOCKED` | 403/503 с WAF/challenge-сигнатурой **или** голый 403 без сообщения о доступе | один повтор текущим маршрутом, затем следующий уровень (в т.ч. браузер L2) | разрешена в бюджете |
| `SOFT_BLOCK` | 2xx, но captcha/challenge/пустая подмена | как `BLOCKED` | разрешена в бюджете |
| `THIN_CONTENT` | 2xx короче порога (204, `{"ok":true}`, тонкий листинг) | сигнал качества данных: чинить профиль/маршрут, не платить | запрещена |
| `PROVIDER_ERROR` | ошибка самого провайдера (в т.ч. его 400/403/404/407/5xx) | ограниченный повтор по текущей документации | не считать успехом |
| `PARSE_FAIL` | контент есть, обязательных данных нет | сохранить снапшот, чинить профиль/экстрактор | запрещена |

> Голый `403` (без сообщения о контроле доступа) трактуется как тихая антибот-защита → `BLOCKED`, чтобы получить бесплатный браузерный повтор, а не терминально «убить» URL. Настоящий «нужен вход» отдаёт `401` или явное сообщение → `ACCESS_DENIED`. `407` — проблема прокси, всегда `PROVIDER_ERROR`.

## Валидация `OK`

Минимум:

- размер тела выше профилированного порога;
- есть канареечная строка/селектор либо обязательные JSON-пути;
- отсутствуют сигнатуры challenge, captcha и access denied;
- content type и схема соответствуют ожидаемым;
- обязательные поля после нормализации не пусты.

Маленькая легитимная страница требует своего порога в Site Profile, а не глобального ослабления проверки.

## Бюджеты повторов

| Вердикт | Бесплатные повторы | Платные попытки |
|---|---:|---:|
| `DEAD_URL` | 0 в текущем прогоне | 0 |
| `ORIGIN_DOWN` | до 3 по расписанию | 0 |
| `RATE_LIMITED` | по `Retry-After` в пределах окна | 0 |
| `AUTH_REQUIRED`, `ACCESS_DENIED` | 0 | 0 |
| `BLOCKED`, `SOFT_BLOCK` | 1 текущим маршрутом | общий cap профиля, обычно не больше 2 |
| `THIN_CONTENT` | 0 сетевых (сигнал качества) | 0 |
| `PROVIDER_ERROR` | ограниченно по политике провайдера | учитывать фактическое списание |
| `PARSE_FAIL` | 0 сетевых | 0 |

## Circuit breaker

- Серия `BLOCKED` по одному домену останавливает оставшуюся очередь до переразведки, чтобы не сжигать бюджет.
- Серия `DEAD_URL` указывает на сломанный источник URL или миграцию раздела.
- Рост `PARSE_FAIL` указывает на дрейф разметки/схемы, а не на проблему доступа.

Точные пороги задавать в Site Profile и проверять на реальном объёме. Стартовый ориентир из research: 20 одинаковых вердиктов подряд.
