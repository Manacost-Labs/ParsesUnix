# Scrape.do

`docs_verified_at: 2026-08-19` — контракт ниже **измерен на живом API**, а не взят
из памяти или из чужого пересказа.

## Роль

Первый платный уровень (L3). Включается только по вердикту `BLOCKED` /
`SOFT_BLOCK` и только через бюджет. Ни `404`, ни `5xx`, ни `PARSE_FAIL` сюда не
эскалируются — и это правило про деньги, а не про стиль (см. измерение ниже).

## Контракт

```
endpoint : https://api.scrape.do/
метод    : GET
токен    : ?token=…   (только из переменной окружения SCRAPE_DO_TOKEN)
цель     : ?url=…     (обязательно URL-encoded)
```

Ключевые параметры: `render`, `super`, `waitSelector`, `geoCode`, `sessionId`,
`disableRetry`.

**`disableRetry=true` мы ставим всегда.** Наш собственный бюджет повторов —
единственный авторитет; повторы провайдера удвоили бы расход и скрыли настоящий
процент отказов.

## Заголовки ответа (измерены, дословно)

Официальная документация их не описывает — имена получены живым запросом:

| Заголовок | Смысл |
|---|---|
| `scrape.do-request-cost` | **фактическая** стоимость вызова |
| `scrape.do-remaining-credits` | остаток на счёте |
| `scrape.do-initial-status-code` | статус **целевого сайта** |
| `scrape.do-request-id` | идентификатор для разбора инцидентов |
| `scrape.do-resolved-url` | финальный URL |
| `scrape.do-detected-waf` | какую защиту увидел провайдер |

`scrape.do-initial-status-code` — самый важный из них. Он отделяет «сайт вернул
404» от «провайдер сломался»: без него живой URL попадал бы в карантин, а
мёртвый — оплачивался бы повторно.

## Измеренная стоимость

Один и тот же тривиальный целевой URL, 2026-08-19:

| Стратегия | Стоимость | Латентность |
|---|---:|---:|
| `normal` | **1** | 1305 мс |
| `render` | **5** | 728 мс |
| `super` | **10** | 486 мс |

Дороже — не значит медленнее: `super` оказался самым быстрым. Выбирать
стратегию по цене, а не по интуиции.

### Мёртвый URL тоже стоит денег

```
GET /definitely-not-here-xyz  ->  target 404,  cost 1 credit
```

Это подтверждено живым вызовом и объясняет два решения в архитектуре: дешёвый
HEAD-sweep обязан отсеивать `404/410` **до** платного уровня, а triage обязан
запрещать эскаляцию `DEAD_URL`. На реальном ответе система так и повела себя:
вердикт `DEAD_URL`, `paid_escalation_allowed = False`.

## Когда какая стратегия

| Стратегия | Когда | Когда **нельзя** |
|---|---|---|
| `normal` | по умолчанию, всё начинается с неё | — |
| `render` | `CSR_REQUIRED`, доказанная потребность в JS | `404`, `410`, `ORIGIN_DOWN`, `PARSE_FAIL` |
| `super` | доказанный `BLOCKED`/`SOFT_BLOCK` | как универсальный fallback |
| `super_render` | последнее средство | как значение по умолчанию |

## Безопасность

- токен читается **только** из окружения или явного аргумента — не из профиля и
  не из конфига, потому что те коммитятся;
- токен не попадает в транслированный ответ (закреплено тестом);
- cookies и заголовки авторизации провайдеру не передаются.

## Стоимость, которую не удалось определить

Если `scrape.do-request-cost` отсутствует, вызов помечается `unattributed` и
считается **не бесплатным**. Молча обнулённый расход — это то, как превышают
бюджет.
