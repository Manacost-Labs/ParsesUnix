# Firecrawl

**docs_verified_at: 2026-08-19** — сверено с живой документацией v2, не по памяти.
Источники: `docs.firecrawl.dev/api-reference/endpoint/scrape`,
`docs.firecrawl.dev/rate-limits`, `firecrawl.dev/pricing`.

Ключей Firecrawl у проекта нет, поэтому **живых измерений нет**. Всё ниже —
документация вендора и наши собственные решения, а не замеры.

## Роль

Управляемый рендеринг и нормализация контента. Firecrawl полезен там, где нужен
чужой браузер и чистый вывод, но **его ответ не является истиной**: тело всё
равно проходит канонический триаж. Идеально отрендеренная в markdown страница
challenge остаётся страницей challenge.

```
Firecrawl → ProviderResponse → триаж → валидация → извлечение → схема
```

## Контракт запроса

```
POST https://api.firecrawl.dev/v2/scrape
Authorization: Bearer $FIRECRAWL_API_KEY
```

Мы всегда просим `formats: ["rawHtml"]` и `onlyMainContent: false`. Markdown
уже выбросил канарейки, JSON-LD и разметку, по которой мы детектируем блок, —
принимать его значило бы отдать вендору право решать, что такое успех.

## Стратегии

| ID | proxy | Рендерит JS | Премиум-сеть | Резерв |
|---|---|---|---|---:|
| `firecrawl:basic` | `basic` | да | нет | 2 |
| `firecrawl:cached` | `basic` + кэш | да | нет | 2 |
| `firecrawl:auto` | `auto` | да | да | 4 |
| `firecrawl:enhanced` | `enhanced` | да | да | 5 |

`auto` документирован как «повтор на enhanced, если basic отказал», то есть один
вызов может стать двумя выборками. Резерв это учитывает, хотя опубликованная
цена — нет.

## Модель стоимости

Документировано: **1 кредит за страницу**. Множители для proxy-режимов
**не опубликованы**, заголовок стоимости в ответе **не документирован**.

Поэтому адаптер оппортунистически ищет `x-credits-used` и родственные, а если их
нет — возвращает `unattributed`. Такой вызов расчитывается как **unknown spend**
и останавливает дальнейшие траты, а не записывается нулём. Это прямое следствие
правила «неизвестная стоимость никогда не равна нулю».

## Кэш — главная ловушка

`maxAge` по умолчанию **172 800 000 мс = 2 суток**. Скрейпер, молча принявший
этот дефолт, публиковал бы двухдневный контент как текущий.

Поэтому:

- обычные стратегии передают `maxAge: 0` — живая выборка;
- стратегия `cached` пользуется кэшем осознанно, но её ответ помечается
  `from_cache=None`, `freshness_provable=False`;
- Firecrawl **не документирует поля с возрастом отданного тела**, поэтому
  доказать свежесть кэшированного ответа нельзя. Недоказуемая свежесть не
  повышает статус данных — устаревшая запись, притворяющаяся текущей, хуже
  честно помеченной устаревшей.

## Безопасность

- Ключ только из окружения `FIRECRAWL_API_KEY`; никогда из профиля или run-конфига.
- `zeroDataRetention` доступен у вендора; включать при работе с чувствительными целями.
- Куки и заголовки авторизации мы не форвардим.

## Ограничения

- Нет ключа → нет живой проверки. Соответствие разбора реальному ответу не измерено.
- Стоимость по режимам не документирована: резервы консервативны намеренно.
- Rate limits зависят от тарифа (10 rpm на free, до 10 000 rpm на Scale).
