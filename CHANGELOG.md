### Added

- **First-class JSON.** `ContentKind`, `detect_content_kind`, экстрактор
  `kind: json` с подмножеством путей и wildcard. Для JSON не строится DOM.
- **Обнаружение внутренних API.** Наблюдение XHR/fetch/GraphQL при рендеринге,
  схемные сигнатуры без значений, подсказки пагинации, вердикты кандидатов.
- **`DiscoveryStore`** — доказательства переживают рестарт; валидация требует
  нескольких **различных** страниц; изменение схемы снимает вердикт.
- **`ws-diagnose --routes`** — сравнение текущего маршрута с найденным API.
- **`ws-probe --discover-api`** — обнаружение из разведки.
- **`tools/benchmark.py`** — синтетическая и реальная нагрузка, накладные
  обнаружения.
- **FinOps 2.0** — `EXACT`/`PROVISIONAL`/`UNKNOWN`, канонические деньги (USD),
  снимки тарифов, дрейф цен.
- **Фазовое исполнение** A/B/C/D с переживанием рестарта.
- **Канарейки** бесплатного и платного слоя.
- **Гейт дрейфа схемы** перед промоушеном.
- **ZenRows** — пять стратегий (`basic`/`js`/`premium`/`js_premium`/`auto`),
  документированные множители кредитов, обнаружение API через `json_response`.
- **Zyte API** — `http`/`browser`/`browser_capture`, чистое разделение статусов,
  обнаружение через `networkCapture`, потолки стоимости от оператора.
- **Reddit и X** за общим социальным контрактом.
- `ws-run --preflight`, `--estimate-cost`, корректное завершение по сигналу.
- **Калибровка флота** — `ws-benchmark providers`: один корпус на всех
  провайдеров, ранжирование по **USD за годный результат**, жёсткие потолки
  трат из окружения, ранняя остановка на лёгких сегментах, изоляция
  доказательств от продакшн-статистики и явное продвижение через предпросмотр.
  По умолчанию **ничего не вызывается**: без `--live` печатается план и худший
  случай в долларах.
- **`ws-benchmark report`** — перечитать сохранённую сессию, не трогая сеть.
- **Матрица статусов и биллинга** по всем пяти вендорам в одном файле:
  живой 404 остаётся 404, отказ вендора никогда не становится вердиктом о
  сайте, неотчитанная стоимость никогда не становится нулём.
- **`docs/operations/provider-calibration.md`** — процедура и её отказы.
- **Site Profile Engineer** — `.agents/skills/site-profile-engineer/`: скилл,
  который не пишет YAML, а **доказывает**, что профиль достаточно надёжен.
- **`site_profiles/`** — реестр и пакеты профилей: `profile.yaml`,
  `corpus.yaml`, `evidence.json`, `README.md`, фикстуры. Пакет — единица
  сертификации и отката, а не один файл.
- **Жизненный цикл профиля** DRAFT → PROBING → VALIDATING → CERTIFIED →
  DEGRADED → QUARANTINED. В `CERTIFIED` ведёт **единственное** ребро — через
  детерминированные проверки. «Выглядит правильно» состоянием не является.
- **Важность полей** `critical` / `important` / `optional`. Старый
  `required_fields` продолжает работать и означает `critical`.
- **Приёмочный корпус** с обязательным негативным случаем и явным
  `NOT_APPLICABLE` там, где вид проверки не имеет смысла.
- **Оценка хрупкости селекторов** STABLE / MEDIUM / FRAGILE. Критическое поле,
  висящее только на хрупком пути, сертификацию не проходит.
- **Мутационное тестирование профиля** — страница ломается специально, чтобы
  выяснить, заметит ли профиль. Мутации **запускаются**, а не подаются файлом.
- **Last known good** и отказ заменять его худшим кандидатом.
- **Здоровье профиля** из реальных прогонов, с окном: одна плохая ночь ничего
  не меняет.
- **Ремонт** предлагает переход на более стабильный источник и **никогда** не
  активируется сам.
- **`ws-profile`** — `list`, `test`, `certify`, `explain`, `diff`, `health`,
  плюс прежние `validate` и `draft` в том же фасаде.

### Fixed

- Неизвестная стоимость превращалась в ноль в трёх местах.
- Тело ответа платного пути читалось без предела.
- Свежесть считалась по `min(max_age)` для всех классов URL.
- Firecrawl: цена в теле, а не в заголовке; `cached` не кэшировала;
  провайдер был недостижим для `BLOCKED`.
- Bright Data: ошибки через HTTP 200; статус цели из несуществующего заголовка.
- `Runner` не вызывал фазы, канарейки, гейт дрейфа и платный слой.
- `Runner` держал `BrowserPool` достижимым из цикла прогона.
- ZenRows: два ложных правила различения сторон, стоимость в долларах вместо
  кредитов; дальше — вендорская цифра в долларах **разбиралась и выбрасывалась**,
  а `json_response` возвращал сырой конверт вместо формы для обнаружения.
- Zyte: имена заголовков в нижнем регистре теряли объявленный тип контента.
- **Нетарифицированная стратегия ранжировалась как бесплатная.** Снимки
  ZenRows и Zyte без ставки оператора строились по `$0` за единицу, поэтому
  ветка роутера «без цены — в конец» была недостижима, и невычислимый вызов
  обгонял все стратегии с известной ценой.
- **scrape.do**: собственные 4xx (кроме 401/403/429) уходили без статуса цели —
  triage читал это как `ORIGIN_DOWN`, нейтральный вердикт, так что провалившаяся
  стратегия не получала штрафа, а URL возвращался в очередь; статус цели 404
  копировался в статус провайдера, и здоровый вендор отчитывался как сломанный;
  заголовок «initial status» — это **первый** хоп, поэтому 308 на редиректе
  превращал готовую страницу в `PARSE_FAIL`.
- **Проверка JSON-путей не умела ходить по массивам.** Эндпоинт, отдающий
  список — самая частая форма листинга, — не проходил валидацию ни при каких
  путях, хотя экстрактор читал те же пути без проблем.
- **Объявленный `Content-Type` был единственным судьёй типа.** Живой провайдер
  вернул 28 КБ настоящего HTML как `text/plain`, и все его страницы
  проваливали валидацию.
- **Экстрактор `json` существовал, но профиль не мог его объявить.** Валидатор
  отвергал единственный вид, написанный для JSON-маршрутов.
- **Проверка путей не понимала `[*]`.** Профиль мог использовать документированный
  синтаксис, корректно извлекать по нему данные — и получать от triage
  «путь отсутствует».
- **Wildcard, разрешившийся в `[None, None, None]`, считался найденным полем.**
  Так поле «продолжает работать» ровно после того изменения API, которое его
  удалило.
- **Секрет в query-строке маршрута не ловился.** Самый вероятный способ, которым
  ключ попадает в закоммиченный профиль.
- **`bool(pagination)` всегда истинно** — секция существует со значениями по
  умолчанию, поэтому «класс пагинируется» было неотличимо от «класс существует».

### Security

- Ограничение размера тела на платном пути.
- Редакция секретов в query найденных маршрутов.
- Кандидаты с `Authorization`/куки отвергаются.
- Найденные URL проходят SSRF-проверку.
- Схемные сигнатуры не содержат значений.
