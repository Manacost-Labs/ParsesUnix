# Калибровка провайдеров

**Вопрос, на который отвечает эта процедура:** какой `provider:strategy` дешевле
всего даёт *годный* результат на конкретном `domain + url_class` — и достаточно
ли доказательств, чтобы на этот ответ опираться.

Не «какой запрос дешевле». Это разные числа, и второе стоит денег:

```
A: $0.0010/запрос, годных 50%  ->  $0.0020 за страницу
B: $0.0015/запрос, годных 99%  ->  $0.0015 за страницу
```

По счёту A дешевле на треть. По факту — дороже на треть.

---

## Запуск

```bash
ws-benchmark providers                 # план: ничего не вызывается, ничего не тратится
ws-benchmark providers --live          # тот же план, но по-настоящему
```

По умолчанию команда **ничего не вызывает**. Она печатает матрицу, которую
собирается прогнать, и худший случай в долларах, если каждый вызов спишет свой
потолок. Первое, что видит оператор, — счёт, на который он соглашается.

### Потолки

Жёсткие, из окружения, потому что поднять их — это видимое действие того, кто
платит:

```bash
MAX_PROVIDER_CALIBRATION_USD=0.50
MAX_SCRAPE_DO_CALIBRATION_USD=0.15
MAX_FIRECRAWL_CALIBRATION_USD=0.15
MAX_BRIGHTDATA_CALIBRATION_USD=0.10
MAX_ZENROWS_CALIBRATION_USD=0.20
MAX_ZYTE_CALIBRATION_USD=0.10
```

Три правила, каждое из-за конкретного способа потерять деньги:

- **держим потолок, списываем факт.** Проверить типовую цену и получить счёт по
  премиальной — так все проверки проходят по отдельности, а сумма нет;
- **неизвестное списание остаётся удержанным.** Провайдер, который ничего не
  сообщил, сделал это не бесплатно;
- **стратегию, которую нечем оценить, нельзя вызывать без присмотра.** Если
  тариф не даёт числа, арифметики потолка не существует. Оператор может
  выстрелить осознанно — `--allow-unbounded`, — и тогда стоимость честно
  остаётся `UNKNOWN` и не попадает ни в одно число.

## Один корпус на всех

Все провайдеры получают **одни и те же** цели и **одни и те же**
`ContentRules`, а судит канонический triage. Отдельного «успеха для бенчмарка»
не существует — иначе бенчмарк измеряет себя.

Стратегия, которую нельзя вызвать, отмечается `INELIGIBLE`. Это другой факт,
чем провал, и он никогда не попадает в success rate.

Порядок обхода — `провайдер -> цена -> сегмент -> цель`, и обе первые позиции
оплачены реальными деньгами:

- обход «по целям» запускал дорогой режим до того, как дешёвый успевал себя
  показать, и ранняя остановка не экономила ничего;
- обход «по сегментам» это чинил, но ломал иначе: вендор тратил лимит на свои
  дорогие режимы раньше, чем дешёвый видел остальной корпус, — и в отчёте
  выглядел как ничего не подтвердивший. Не потому что не смог, а потому что не
  дошёл.

## Что считается

| Метрика | Зачем |
|---|---|
| **USD за годный результат** | главное число |
| Wilson lower bound | одна удача — не вероятность |
| status fidelity | сообщил ли вендор статус, который реально даёт сайт |
| p50 / p95 | дороже ≠ быстрее (измерено) |
| exact / provisional / unknown | три разные вещи, никогда не складываются молча |
| discovery candidates | найденные эндпоинты, **не** «сэкономленные вызовы» |

Два отказа считать:

- **любая неатрибутированная трата дисквалифицирует отношение.** Числитель
  становится нижней границей, и частное занижало бы цену. Отчёт говорит
  «не вычисляется» и объясняет почему;
- **нейтральные исходы — не провалы.** Мёртвый URL, честно описанный вендором,
  это вендор, сделавший свою работу.

## Изоляция и продвижение

Калибровка пишет в свою директорию. Продакшн-статистика меняется **только**
так:

```bash
ws-benchmark promote --production-stats .state/provider_stats.sqlite3    # предпросмотр
ws-benchmark promote --production-stats .state/provider_stats.sqlite3 --yes
```

Предпросмотр перечисляет каждый ключ поимённо — агрегат может спрятать
сюрприз. Без `--yes` не пишется ничего.

## Перечитать сессию, ничего не вызывая

```bash
ws-benchmark report --session <id> --min-confidence 0.5
```

Прочтение измерения меняется чаще, чем само измерение. Перезапускать сеть ради
нового заголовка таблицы — значит тихо ответить на другой вопрос новыми словами.

## Чего процедура не делает

- не продвигает маршруты;
- не меняет вердикт провайдера в `PRODUCTION_READINESS.md`;
- не балансирует нагрузку между вендорами — концентрация **показывается**, а
  решение остаётся за оператором;
- не считает «сэкономленные браузерные вызовы» для эндпоинта, который всего
  лишь `PROMISING`.
