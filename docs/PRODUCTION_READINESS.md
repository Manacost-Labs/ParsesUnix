# Production readiness

**Дата оценки:** 2026-08-19 · **Коммит:** см. `git log -1`

## Вердикт

```
GO — для бесплатного ядра (L0–L2) и для платного слоя через Scrape.do
NO-GO — для автоматических платных прогонов через Firecrawl и Bright Data
```

Разделение не формальность. Бесплатное ядро и Scrape.do проверены живыми
вызовами и интеграционными тестами через настоящий `Runner`. Firecrawl и
Bright Data написаны по документации, ключей нет, **ни один реальный ответ
этих вендоров не разбирался**. Запускать на них unattended-прогон с бюджетом
значит доверять непроверенному коду распоряжаться деньгами.

## Что закрыто в этой итерации

| Было | Стало |
|---|---|
| `Runner` не вызывал фазы, канарейки, дрейф и платный слой | конвейер соединён, 25 интеграционных тестов через настоящий `Runner` |
| Свежесть по `min(max_age)` для всех классов | окно каждого класса; отчёт по классам |
| Нет записи «за этот URL уже платили» | `PaidAttemptLedger`, запись **до** резервации |
| Фаза, не берущая URL, теряла его | `QueueStore.defer` возвращает в очередь |
| SIGTERM убивал прогон | корректное завершение между URL |
| Конфигурационная ошибка находилась в середине прогона | `ws-run --preflight` |
| Тело ответа платного пути читалось без предела | потолок 8 МБ + видимое усечение |

## Доказанные инварианты

Каждый проверен **мутацией**: при порче реализации тесты падают.

| Инвариант | Мутация | Результат |
|---|---|---|
| Платить можно только по BLOCKED/SOFT_BLOCK | снять политику | FAILED |
| Неизвестная стоимость ≠ ноль | вернуть ноль | FAILED (10) |
| Удерживается worst case | резервировать номинал | FAILED |
| Фаза A не может тратить | дать ей платный шлюз | FAILED |
| URL не оплачивается дважды | разрешить повтор | FAILED (3) |
| Дрейф блокирует промоушен | обойти гейт | FAILED |

Мутация «фаза A получает платный шлюз» сначала **выжила**: первый тест
проверял лишь отсутствие платного шлюза, второй бросал исключение из sentinel,
которое `_process_guarded` глушит по замыслу. Ловит её только подсчёт вызовов.

## Проверено вживую

| Что | Как |
|---|---|
| Scrape.do: заголовки, стоимости, 404 стоит кредит | живые вызовы |
| Сквозной платный путь L1→L3 | живой: удержано 3, списан 1, удержание снято |
| `--estimate-cost` | 40 URL → 42.00 ожидаемых, 120 удержания, 0 платных вызовов |
| `--preflight` | корректно отверг бюджет без ключей |
| Соак | 2k / 10k / **100 000** URL |
| Браузер | 5 живых тестов Playwright |

## НЕ проверено вживую

| Что | Почему |
|---|---|
| Firecrawl | нет `FIRECRAWL_API_KEY` |
| Bright Data | нет `BRIGHTDATA_API_KEY` / зоны |
| Bright Data Browser API | нужна отдельная зона |
| Нагрузка: p50/p95/RSS/URLs-per-sec | бенчмарка не было; §59 — не оптимизировать без измерения |

## Требуемое окружение

```bash
SCRAPE_DO_TOKEN=...        # опционально; без него платный слой не активируется
FIRECRAWL_API_KEY=...      # опционально
BRIGHTDATA_API_KEY=...     # опционально
BRIGHTDATA_ZONE=...        # обязательно вместе с ключом
BRIGHTDATA_BROWSER_ZONE=...# только для Browser API
```

Python 3.11–3.13. `pip install -e '.[browser]'` + `playwright install chromium`
для L2.

## Чеклист перед запуском

```
[ ] ws-run config.json --preflight          → ok: true
[ ] ws-profile validate                     → профиль валиден
[ ] ws-run config.json --estimate-cost      → влезает в бюджет
[ ] бэкап state/*.sqlite3 существует
[ ] free canary PASS или осознанно принятый WARN
[ ] paid canary PASS (если платный слой включён)
```

## Что бэкапить

```
state/queue.sqlite3            очередь и учёт URL
state/budget.sqlite3           деньги — критично
state/paid_attempts.sqlite3    «за этот URL уже платили» — критично
state/dataset.sqlite3          LKG
state/freshness.sqlite3        окна свежести
state/route_stats.sqlite3      выученные маршруты
state/provider_stats.sqlite3   статистика провайдеров
state/provider_breakers.sqlite3
state/phases.sqlite3           позиция в фазах
state/fingerprints.sqlite3
```

Потеря `budget.sqlite3` или `paid_attempts.sqlite3` означает потерю защиты от
повторной оплаты. Остальное восстановимо ценой повторного обучения.

## Восстановление

| Ситуация | Действие |
|---|---|
| Процесс упал | просто запустить снова: фазы продолжаются с места падения |
| `UNKNOWN_SPEND` | `ws-budget recover`, затем `reconcile` по панели вендора |
| Зависшие `STARTED` в paid_attempts | сверить по вендору; до сверки URL не оплачивается повторно |
| Дрейф заблокировал промоушен | потребитель на LKG; разобрать `explain()` |
| Канарейка `BLOCK_RUN` | прогон не стартовал, данные не тронуты |
| Повреждение SQLite | восстановить из бэкапа; при потере route/provider stats система переучится |

## Известные ограничения

1. **Firecrawl и Bright Data не проверены вживую.** Главное ограничение.
2. **Reddit и X не реализованы** (§60–78 предыдущего брифа).
3. **Нет нагрузочного бенчмарка** — p50/p95/RSS не измерены.
4. **Обнаружение XHR-маршрутов** после рендеринга не реализовано.
5. **Плановые веса Bright Data — наша шкала**, а не тариф вендора.
6. **`main` без branch protection** — рекомендация: требовать PR и зелёный CI,
   запретить force-push. Не менял автоматически.

## Рекомендация

Запускать на бесплатном ядре и Scrape.do. Перед включением Firecrawl или
Bright Data провести capped live acceptance с жёстким лимитом расходов.
