Предыдущий NO-GO по Firecrawl и Bright Data **снят**: оба проверены живыми
вызовами сквозь настоящий шлюз и реестр. **Все пять провайдеров проверены
вживую, и в каждом нашёлся дефект,** невидимый документации, типам и тестам.

## Что нашла живая проверка провайдеров

Ни один из этих дефектов не был виден документации, типам или тестам.

| Дефект | Последствие |
|---|---|
| Firecrawl сообщает цену в теле, не в заголовке | каждый вызов — неатрибутированная трата, бюджет вставал |
| Стратегия `cached` не кэшировала | называла поведение, которого не имела |
| Firecrawl недостижим для `BLOCKED` | провайдер настроен, оценён и **никогда не использовался** |
| Bright Data сообщает ошибки через HTTP 200 | ошибка конфигурации записывалась как вердикт о сайте |
| Статус цели из несуществующего заголовка | мёртвые URL оплачивались бы каждый прогон |
| ZenRows: `X-Request-Id` не различает стороны | ошибка провайдера шла бы в триаж как статус цели |
| ZenRows: 404 цели приходит как problem+json | живой мёртвый URL стал бы ошибкой провайдера |
| ZenRows: стоимость в долларах, не кредитах | модель тарифов считала бы не то |
| Zyte: имена заголовков в нижнем регистре | объявленный тип контента терялся |
| ZenRows: доллары вендора разбирались и выбрасывались | точная цена подменялась нашей арифметикой |
| Нетарифицированная стратегия стоила `$0` | она обгоняла все стратегии с известной ценой |
| scrape.do: свои 4xx без статуса цели | провал стратегии выглядел как `ORIGIN_DOWN` и не штрафовался |
| scrape.do: статус цели 404 → статус провайдера | здоровый вендор отчитывался как сломанный |
| scrape.do: «initial status» — первый хоп | 308 на редиректе делал готовую страницу `PARSE_FAIL` |
| Валидация JSON-путей не ходила по массивам | листинг-эндпоинт не проходил проверку никогда |
| Тип контента судился только по заголовку | 28 КБ HTML как `text/plain` = провал всех страниц вендора |

Последний нашёлся вопреки существующему тесту, который **проходил**: тест
использовал то же неверное имя заголовка, что и код. Тест, написанный из
ошибочного допущения реализации, её не проверяет.

## Измерено

### Провайдеры

| Провайдер | Режим | Стоимость | Латентность |
|---|---|---:|---:|
| Scrape.do | normal / render / super | 1 / 5 / 10 кредитов | 1305 / … / 486 мс |
| Firecrawl | basic / cached / auto / enhanced | 1 / 1 / 1 / 1 кредит | 1567 / 813 / 1535 / 2865 мс |
| Bright Data | unlocker | CPM, не сообщается | — |

Измерения Firecrawl сделаны на **лёгкой** цели и не обобщаются: что берёт
stealth-пул на сопротивляющемся сайте, не опубликовано и не измерено.

### Производительность

| Нагрузка | Результат |
|---|---|
| Синтетика, 10 000 URL | 343.9 URL/сек, 2.91 мс/URL, 55.8 МБ пик |
| Реальная сеть, 100 URL | 100% валидных, p50 665 мс, p95 823, p99 1056 |
| Накладные обнаружения | **0.17 мс** на наблюдение, 0.4 МБ |

Синтетика измеряет машинерию и **не является** сетевым бенчмарком; в отчёте эти
две нагрузки не смешиваются.

## Доказанные мутациями инварианты

| Инвариант | При порче |
|---|---|
| Кандидат с `Authorization` непригоден | FAILED (4) |
| Приватный эндпоинт отвергается | FAILED (5) |
| Сигнатура схемы — форма, не значения | FAILED (2) |
| JSON не строит DOM | FAILED (1) |
| Кандидат не продвигается без валидации | FAILED (1) |
| Одна страница не валидирует эндпоинт | FAILED (4) |

Плюс ранее доказанные: платить только по `BLOCKED`/`SOFT_BLOCK`, неизвестная
стоимость ≠ ноль, удерживается worst case, фаза A не может тратить, URL не
оплачивается дважды, дрейф блокирует промоушен.

## Известные ограничения

1. **Автоматического продвижения маршрутов нет и не планируется.** Черновик
   читает человек. Эндпоинт, ответивший при рендере, — не согласие его вызывать.
2. **Reddit не проверен вживую** — нет OAuth-учётных данных. Плюс Reddit
   блокирует user-agent этого проекта, поэтому его документацию не удалось
   прочитать у вендора; формы эндпоинтов взяты из вторичных источников.
3. **X: публичный путь не проверен вживую.** API выключен по умолчанию.
4. **Bright Data требует `BRIGHTDATA_CPM_USD`** — без ставки каждый вызов даёт
   `UNKNOWN` и останавливает платную работу. При включённых premium domains
   указывать премиальную ставку: граница обязана быть худшим случаем.
5. **Размер выборки бенчмарка мал** — 100 реальных URL. Достаточно для формы
   распределения, недостаточно для утверждений о хвостах.
6. **Bright Data Browser API не оценён** — отдельный продукт на отдельном
   тарифе, остаётся `UNKNOWN`.
7. **ZenRows запрещает часть доменов** кодом `REQS001` — включая песочницы
   `toscrape.*`. Это отказ провайдера, а не вердикт о цели. Измерено также:
   он объявляет HTML как `text/plain`, а его `js_render` на живой SvelteKit-цели
   дорендерил 5 387 Б против 51 797 Б локального Chromium и вернул **пустой**
   список XHR.
8. **Zyte требует потолков от оператора** (`ZYTE_HTTP_MAX_USD` и родственные) —
   его цена зависит от уровня сайта и не выводима из запроса.
10. **Сверка расходов Zyte через Stats API не реализована.**
11. **`main` без branch protection.** Рекомендация ниже; автоматически не менял.
