# Планирование прогонов, окна и sweep

Дополняет `workflow.md` (уровни) и `reliability.md` (надёжность группы URL). Здесь —
как гонять группы URL по расписанию так, чтобы полнота была видимой, а стоимость
и нагрузка — управляемыми.

## Единица работы: прогон в окне

Прогон — это одно исполнение раннера (`ws-run <run-config.json>`) внутри окна
(обычно ночного, 02:00–06:00). Прогон:

1. **Resume.** Любая строка `IN_PROGRESS` — это упавший прошлый прогон; она
   возвращается в очередь. Повторный запуск не создаёт дублей (идемпотентный
   ключ = нормализованный URL + content-hash).
2. **Freshness re-crawl.** `DONE`-URL, у которых истёк адаптивный интервал,
   переоткрываются. Условный запрос (`ETag`/`Last-Modified`) даёт `304`
   (`NOT_MODIFIED`) → страница не скачивается заново.
3. **Основной проход.** Каждый URL идёт по бесплатным маршрутам L0→L1→L2, каждый
   ответ проходит triage. `404/410` → карантин; «не берётся ничем» за N прогонов
   → dead zone (алерт).
4. **Извлечение и запись.** Экстракторы + кворум → staging → валидация целиком →
   атомарный promote или reject с сохранением LKG.
5. **Отчёт.** `state/last-report.json`: coverage, вердикты, fallback, источники
   экстракторов, freshness, unresolved и dead zones.

## Sweep (фаза A) — дешёвый предварительный отсев

Перед основным проходом можно прогнать лёгкий `HEAD`/range-`GET` sweep, чтобы
отсеять `404/410` в карантин **до** дорогих шагов. Для бесплатного ядра это
оптимизация (мёртвые URL и так уходят в карантин на основном проходе). Она
становится **обязательной** перед платными уровнями, потому что провайдеры
(например scrape.do) списывают деньги за `404/410`. Не подключать платные
адаптеры раньше, чем sweep отсеивает мёртвые URL.

## Бюджет окна и конкуренция

- У прогона есть дедлайн (`deadline_seconds`) — он не выходит за окно. Недобор
  переносится в следующий прогон через очередь, молчаливых пропусков нет.
- Вежливость на домен: интервал с джиттером и `Retry-After`; `crawl_delay` из
  robots. Circuit breaker останавливает домен после серии одинаковых
  `BLOCKED`/`ORIGIN_DOWN`.
- `RATE_LIMITED`/`ORIGIN_DOWN` не эскалируют уровень — они переносятся отложенным
  retry внутри окна или в следующий прогон.

## Периодическая полная ревизия

Раз в месяц — прогон с `--full-review`: игнорирует freshness-интервалы,
перечитывает весь корпус, проверяет, не «сползли» ли экстракторы (провенанс
`extractor_source`) и держит ли freshness SLO. Это же — момент ретеста
даунгрейда уровней (аксиома: раз в месяц проверять, не работает ли снова более
дешёвый уровень).

## Развёртывание

systemd-timer на сервере: `deploy/web-scraper.timer` (ночное окно) и
`deploy/web-scraper-review.timer` (месячная ревизия). Деплой — `git pull` +
`pip install -e .`. Состояние переживает деплой; прерванный деплоем прогон
продолжается с очереди. Подробности — `deploy/README.md`.
