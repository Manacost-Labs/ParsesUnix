# Рабочий процесс и лестница получения

## Содержание

1. Порядок разведки
2. Уровни доступа
3. Порядок одного запроса
4. Работа с группой URL
5. Критерии готовности

## 1. Порядок разведки

Для нового домена сначала зафиксировать цель, классы URL и обязательные поля. Затем:

1. Запустить `scripts/probe.py` для репрезентативной страницы каждого класса.
2. Проверить `robots.txt`, sitemap, RSS/Atom, JSON-LD, `__NEXT_DATA__`, ссылки `amphtml` и статические признаки JSON API.
3. Если страница клиентская, один раз исследовать сетевые ответы браузера и сохранить найденный API в Site Profile. Не считать статический probe доказательством отсутствия API.
4. Проверить 20–50 URL на выбранном бесплатном уровне и получить распределение вердиктов.
5. Эскалировать только `BLOCKED` и `SOFT_BLOCK`. Ошибки origin, скорость, мёртвые URL и сломанные селекторы решать отдельно.

## 2. Уровни доступа

| Уровень | Метод | Начинать, когда |
|---|---|---|
| L0 | Публичный/внутренний JSON API, RSS, sitemap, структурированные данные | Всегда проверять первым |
| L1 | HTTP с браузерным TLS/HTTP-профилем | Страница SSR, нет JS-челленджа |
| L2 | Локальный браузер или stealth-браузер | Нужен рендер или доказан браузерный challenge |
| L3 | Платный провайдер без дорогого residential режима | L2 устойчиво не даёт требуемую полноту |
| L4 | Residential/Web Unlocker | Более дешёвые маршруты исчерпаны и причина задокументирована |

Python — основной стек. Rust применять для большого стабильного L1-потока, когда выгода одного бинарника и пропускной способности измерима.

## 3. Порядок одного запроса

```text
freshness gate
  -> известный L0 маршрут
  -> основной маршрут на уровне политики
  -> triage и валидация контента
  -> бесплатные alt_routes на том же уровне
  -> следующий уровень только для BLOCKED/SOFT_BLOCK
  -> снапшот, метрики и итоговый вердикт
```

Если ответ медленнее исторического p95, допустимо хеджировать только бесплатным маршрутом. Не запускать два платных запроса ради латентности.

## 4. Работа с группой URL

- Дедуплицировать нормализованные URL до сети.
- Сначала делать дешёвый sweep, чтобы не отправлять известные 404/410 в платный канал.
- Хранить очередь и чекпойнт; повторный запуск продолжает работу без дублей.
- Ограничивать конкуренцию по домену, добавлять jitter и соблюдать `Retry-After`.
- Каждый URL заканчивает прогон с данными или явным вердиктом. Молчаливого пропуска нет.
- Сверять фактический объём с sitemap, счётчиком листинга или ожидаемым диапазоном.

## 5. Критерии готовности

Готовность нового парсера подтверждается отдельно:

- репрезентативные страницы прошли валидацию данных;
- 404/410 и origin failures не породили платные запросы;
- пустой или challenge-ответ с `200` не принят за успех;
- повторный запуск идемпотентен;
- отчёт показывает coverage, вердикты, fallback, стоимость и unresolved URL;
- для расписания проверено восстановление после прерывания.
