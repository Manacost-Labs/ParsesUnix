# Runbook: большой прогон

Порядок операций перед, во время и после крупного платного прогона.

## 1. Перед прогоном — бесплатная канарейка

Проверяет, что сайт всё ещё тот, под который написан профиль.

```python
from web_scraper.finops import FreeCanary, CanaryUrl

outcome = FreeCanary().run(candidates, fetch=gateway.fetch_url)
```

| Статус | Что делать |
|---|---|
| `PASS` | запускать |
| `WARN` | запускать и смотреть; в отчёте названы страты, где ничего не решилось |
| `BLOCK_RUN` | **не запускать** |

`BLOCK_RUN` с формулировкой «profile drift, not an outage» означает редизайн:
страницы отдавались нормально и ни одна не разобралась. Прогон на 100k произвёл бы
непригодный датасет и потратил бы платный бюджет по дороге.

## 2. Одобрение бюджета

```bash
ws-run run.json --estimate-cost
```

Смотреть **три** числа, а не одно:

- `expected` — плановая цифра;
- `reserved` — сколько будет **удержано** (всегда больше);
- `worst case` — насколько плохо может быть.

Пригодность считается по **удержанию**. Прогон, одобренный по expected, встаёт на
60% с бюджетом, съеденным холдами. Exit code ≠ 0 означает «не влезает» — cron,
проверяющий только статус, такой прогон не запустит.

Отдельно проверить `unroutable`: это URL, которым ни одна стратегия не проходит
порог уверенности. Они ничего не стоят и останутся нерешёнными — это факт о
покрытии, который нужно знать **до** одобрения.

## 3. Платная канарейка

Перед большим платным батчем 3–10 представительных URL идут тем же путём.

| Статус | Что делать |
|---|---|
| `PASS` | продолжать |
| `WARN` | продолжать, следить |
| `BLOCK_PAID_PHASE` | **остановить**: батч только размножит эту неудачу |

Нейтральные вердикты (мёртвый URL, лежащий origin) из подсчёта исключаются.

## 4. Запуск

Прогон идёт фазами:

```
A  free            все URL, L0–L2, платный вызов недостижим
B  free retry      только то, что чинится само
C  cheap paid      остаток, дешёвые стратегии
D  expensive paid  только то, что дешевле не берётся
```

Фаза B — там, где основная экономия. 800 URL, упавших на пятиминутном сбое
origin, не превращаются в 800 платных вызовов.

## 5. Наблюдение

| Сигнал | Значение |
|---|---|
| `unknown_spend` | **критично**: деньги ушли без подтверждения, траты остановлены |
| `paid_share_spike` | обычно регресс бесплатного слоя, а не «сайты стали сложнее» |
| `fallback_provider_spike` | дешёвые стратегии тихо перестали работать |
| `cost_per_valid_result_spike` | каждый пригодный результат дорожает |
| `PRICING_DRIFT` | вендор списал больше документированного потолка |

## 6. Инцидент

Полный разбор — [`provider-incidents.md`](provider-incidents.md). Кратко:

```bash
ws-budget --db state/budget.sqlite3 pending
ws-budget --db state/budget.sqlite3 recover --dry-run
ws-budget --db state/budget.sqlite3 recover
```

`recover` выходит с ненулевым кодом, пока деньги не сведены.

## 7. Сверка

Найти запрос по `provider_request_id` в панели вендора и записать факт —
**включая ноль**, если списания не было:

```bash
ws-budget --db state/budget.sqlite3 reconcile \
    --reservation-id <id> --actual-credits 1 --detail "панель провайдера"
```

«Я проверил, списания не было» — легитимный вывод. Он отличается от того, что
система сама предположила бы ноль.

## 8. Промоушен

Перед публикацией сравнивается форма датасета с последним здоровым:

| Вердикт | Значение |
|---|---|
| `PASS` | опубликовать |
| `PASS_WITHOUT_BASELINE` | первый прогон; **дрейф не оценивался** |
| `WARN` | опубликовать, посмотреть отчёт |
| `BLOCK_PROMOTION` | не публиковать; потребитель видит LKG |

Особое внимание — `provenance_degraded`: значения выглядят правдоподобно, но
приходят от более слабого экстрактора.

## 9. Откат

Промоушен атомарен. Заблокированный промоушен **не разрушает** LKG: потребитель
продолжает видеть прежнюю версию. Отката как отдельного действия не требуется.

## Что после падения

Процесс, умерший в фазе C, возобновляется **в фазе C**. Перезапуск платных фаз
оплатил бы те же URL дважды.

Резервация в состоянии `RESERVED` не дошла до провайдера — освобождается.
`SUBMITTED` могла быть списана — остаётся удержанной и переходит в `UNKNOWN`.
Восстановление идемпотентно.
