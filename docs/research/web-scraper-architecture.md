# Архитектура скилла `web-scraper`

Цель: получать данные страниц по расписанию с итоговой полнотой ~100% живых URL
за окно прогона, при минимальной стоимости. Деньги (scrape.do, Firecrawl,
Bright Data, residential) тратятся только тогда, когда классификатор доказал,
что бесплатные уровни не работают. Ни один URL не теряется молча: он либо
получен, либо имеет вердикт и попадает в отчёт.

---

## 0. Аксиомы (нарушать нельзя)

1. **Эскалация на платный канал разрешена только по вердикту BLOCKED или
   SOFT_BLOCK.** Никогда по 404, 410, 5xx, таймауту, DNS-ошибке.
2. **Ни одного запроса без прохода через классификатор** (`triage`). Любой
   ответ — включая 200 — получает вердикт до того, как принято решение
   о ретрае.
3. **Ретраи имеют бюджет.** Нет бесконечных повторов ни на одном уровне.
4. **Перед парсингом HTML — поиск скрытого API.** JSON-эндпоинт без защиты
   дешевле любого обхода.
5. **Перед первым парсером нового сайта — probe.** Никаких «сразу residential,
   чтобы наверняка».
6. **Документация провайдеров сверяется онлайн** (web_fetch на docs.scrape.do,
   docs.firecrawl.dev, docs.brightdata.com) перед генерацией кода, использующего
   их API. В reference-файлах хранится дата последней сверки.
7. **Каждое использование уровня 3–4 фиксируется в коде комментарием**:
   дата, симптом, почему нижние уровни не сработали. Раз в месяц — ретест
   даунгрейда.
8. **Дневной денежный лимит** на платные запросы. Превышение → стоп + алерт,
   не молчаливое продолжение.

## 2. SKILL.md — логика роутера

Триггеры: «напиши парсер», «спарси сайт», «почему меня банит», «сколько стоит
парсить X», «настрой scrape.do / Firecrawl / Bright Data», «404/502 при
парсинге», «парсер на Rust/Python», упоминание Scrapy/Scrapling/Playwright
в контексте скрейпинга.

Режимы (по формулировке запроса):

| Запрос | Что читает скилл | Что делает |
|---|---|---|
| Новый сайт | escalation-ladder, hidden-api | Сначала запуск probe.py, потом выбор уровня |
| «Меня банит / ошибки» | error-triage, detection | Диагноз по логам/ответам, НЕ эскалация вслепую |
| «Дорого выходит» | retry-policy, comparison | Аудит: какие вердикты уходили в платный канал |
| Прод по расписанию | scheduling + шаблон scheduler_run | Каскад + sweep + отчёт |
| Выбор провайдера | comparison + сверка живых доков | Таблица решения, не «любимый» провайдер |
| Rust или Python | правило выбора (§7) | По объёму и уровню, не по вкусу |

Порядок работы над любым новым парсером (жёсткий, зашит в SKILL.md):

```
1. probe.py → протокол разведки (защита, CSR/SSR, sitemap, скрытый API)
2. Если найден API → парсер по API, уровни не нужны. КОНЕЦ.
3. Выбор стартового уровня по протоколу probe
4. Генерация парсера из шаблона (каскад всегда, даже если стартовый L1)
5. Тестовый прогон на 20–50 URL → распределение вердиктов
6. Если BLOCKED > 5% → пересмотр уровня, НЕ увеличение ретраев
7. Прод: расписание + sweep + отчёт + бюджет
```

## 3. Классификатор `triage.py` (ядро скилла)

Единственная точка, где ответ превращается в решение. Встраивается во все
шаблоны (Python — модуль, Rust — порт того же enum и таблицы).

### Вердикты

| Вердикт | Сигнатура | Действие | Платный ретрай |
|---|---|---|---|
| `OK` | 2xx + контент проходит валидацию (§3.2) | сохранить | — |
| `DEAD_URL` | 404/410; повторно 404 в другой день | карантин | **запрещён** |
| `ORIGIN_DOWN` | 502/504/522/523/timeout, сайт лежит и в браузере | ретрай через 5м/30м/2ч тем же уровнем | **запрещён** |
| `RATE_LIMITED` | 429, либо серия 403 после N успешных | backoff ×2, конкурентность ÷2 | **запрещён** (это не блок, это скорость) |
| `BLOCKED` | 403/503 + сигнатуры CF («Just a moment», cf-mitigated), PerimeterX (_px), DataDome | 1 ретрай текущим уровнем → ступень вверх | разрешён |
| `SOFT_BLOCK` | 200, но: пустой body, капча в HTML, контент < порога, honeypot-страница | как BLOCKED | разрешён |
| `PROVIDER_ERROR` | 5xx от самого провайдера (scrape.do/BrightData) | ретрай ×3 — по их биллингу не оплачивается, но сверить политику | бесплатен по правилам провайдера |
| `PARSE_FAIL` | 200, контент есть, но селекторы не нашли данные | алерт «сайт сменил вёрстку», НЕ ретрай | **запрещён** |

Ключевые тонкости:

- **404 ≠ блок по умолчанию.** Один раз на домен проверяется гипотеза
  «404 ботам»: тот же URL уровнем 2 (реальный браузер). Если и там 404 —
  все дальнейшие 404 домена считаются честными без перепроверки.
- **RATE_LIMITED не эскалируется.** Смена IP на residential при 429 — трата
  денег на проблему, которая решается снижением скорости.
- **PARSE_FAIL отделён от SOFT_BLOCK** порогом и сигнатурами: страница-капча
  и страница с новой вёрсткой — разные диагнозы и разные действия.

### 3.2 Валидация контента (обязательна для вердикта OK)

200 — это не успех, пока контент не проверен:

- длина body > минимального порога (настраивается на сайт)
- присутствует «канареечный» селектор/строка, которая есть на каждой целевой
  странице (заголовок статьи, цена, дата)
- отсутствуют стоп-сигнатуры (капча, «access denied», интерстишл)
- для JSON: схема валидна, обязательные поля не null

Без этого каскад радостно сохранит 500 страниц «Just a moment...» со статусом
«успех» — второй по частоте способ получить 0% данных при 100% зелёных логов.

## 4. Лестница эскалации `escalation-ladder.md`

| Ур. | Метод | Python | Rust | Стоимость | Когда стартовать здесь |
|---|---|---|---|---|---|
| 0 | Разведка + скрытый API | probe.py, httpx | rquest | ~0 | всегда сначала |
| 1 | HTTP с браузерным fingerprint + DC-прокси | curl_cffi / Scrapling Fetcher | **rquest** (не reqwest — JA3) | ~0 | probe: нет JS-челленджа |
| 2 | Локальный headless stealth | Scrapling StealthyFetcher, patchright, scrapy-playwright; точечно DrissionPage-CF | chromiumoxide (без stealth-преимуществ) | CPU | probe: CSR или managed challenge |
| 3 | Провайдер без residential | scrape.do (base), Firecrawl (нужен markdown/extract) | HTTP-вызов API | $ | L2 стабильно < 95% успеха |
| 4 | Residential / Unlocker | scrape.do super=true, Bright Data Web Unlocker | HTTP-вызов API | $$$ | L3 стабильно < 95%, зафиксировано комментарием |

Правила переходов:

- Вверх: только по вердиктам BLOCKED/SOFT_BLOCK, при доле > 5% на тестовой
  выборке или устойчиво в проде.
- Вниз (обязательный ежемесячный ретест): 20 URL нижним уровнем; если ≥ 95%
  успеха — даунгрейд. Защиты сайтов не только усиливаются, но и ослабевают,
  а платный уровень без ретеста остаётся навсегда.
- Каскад в проде: парсер всегда содержит свой уровень + одну-две ступени
  fallback. 90%+ запросов должны проходить основным (дешёвым) уровнем;
  если fallback ловит > 10% — это сигнал пересмотреть основной уровень,
  а не норма жизни.

## 5. Retry-политика и бюджеты `retry-policy.md`

### Бюджеты на URL за прогон

| Вердикт | Бесплатные ретраи | Платные запросы (все уровни 3–4 суммарно) |
|---|---|---|
| DEAD_URL | 0 (1 перепроверка на следующий день) | 0 |
| ORIGIN_DOWN | 3 (5м / 30м / 2ч) | 0 |
| RATE_LIMITED | по backoff, без смены канала | 0 |
| BLOCKED / SOFT_BLOCK | 1 + эскалация | **максимум 2** |
| PROVIDER_ERROR | 3 | не тарифицируются |

### Circuit breaker по домену

- 20 BLOCKED подряд → домен на паузу до конца прогона + алерт. Не досжигать
  бюджет на оставшиеся URL той же защитой.
- 20 DEAD_URL подряд → вероятно, сломан источник URL (сменились слаги,
  переехал раздел) → пауза + алерт «проверь sitemap».

### Карантин URL

SQLite-таблица `quarantine(url, first_404, last_check, checks)`. URL с 404
в два разных дня — карантин; перепроверка раз в неделю уровнем 1; три
недельных 404 — архив навсегда. Карантинные URL не попадают в очередь
прогона вообще.

### Дневной денежный лимит

`budget.py` ведёт счётчик платных запросов по каждому провайдеру
(перевод в валюту по прайсу из providers/*.md). При достижении лимита —
платные уровни отключаются до полуночи, каскад работает только L1–L2,
алерт в Telegram. Лимит задаётся в конфиге прогона, дефолт консервативный.

## 6. Расписание и достижение «100%» `scheduling.md`

Полнота достигается не идеальным одиночным запросом, а конструкцией прогона:

```
Прогон (окно, напр. 02:00–06:00):
  Фаза A. head_sweep.py — HEAD/лёгкий GET уровнем 1 по всей очереди.
          Отсев DEAD_URL до того, как они попали в основной цикл.
  Фаза B. Основной проход каскадом. Каждый URL → вердикт → сохранение
          или очередь ретраев с меткой времени.
  Фаза C. Sweep отложенных ретраев (ORIGIN_DOWN через 30м/2ч и т.п.).
  Фаза D. report.py:
          - получено / всего живых (целевая метрика, должна быть ~100%)
          - распределение вердиктов
          - потрачено платных запросов и денег, по провайдерам
          - success rate основного уровня (если < 90% — предупреждение)
          - список PARSE_FAIL (сменилась вёрстка — чинить селекторы)
          → лог в ClickHouse, алерт в Telegram при отклонениях
```

Определение успеха прогона: **все URL вне карантина имеют вердикт OK либо
ORIGIN_DOWN с исчерпанным бюджетом** (сайт физически лежал всё окно — эти URL
автоматически первыми идут в следующий прогон). Всё остальное — инцидент,
который виден в отчёте, а не тихая дыра в данных.

Гигиена скорости (снижает саму вероятность блокировок):
- конкурентность на домен ≤ 2–4, jitter 30–100% к базовой задержке
- уважение Retry-After
- прогон в «тихие часы» таймзоны сайта
- Scrapy: AUTOTHROTTLE включён всегда

## 7. Python vs Rust — правило выбора

- **Python — дефолт.** Scrapling для точечных задач, Scrapy (+ triage
  middleware из шаблона) для обхода сайтов целиком. Весь антибот-инструментарий
  уровня 2 (patchright, camoufox, DrissionPage) существует только здесь.
- **Rust — когда одновременно:** парсер работает уровнем 1, объём большой,
  прод по расписанию, ценен один бинарник без окружения. Стек: rquest
  (браузерный TLS/HTTP2-fingerprint) + scraper + tokio. `reqwest` в чистом
  виде запрещён для внешних сайтов — детектится по JA3.
- Уровень 2 на Rust не даёт преимуществ (узкое место — Chromium), шаблон
  каскада на Rust делает fallback через HTTP-вызов провайдера, не через
  локальный браузер.
- Оба стека используют один и тот же `error-triage.md` как источник истины:
  таблица вердиктов портирована в оба шаблона и обязана совпадать.

## 8. Документация провайдеров `providers/`

Каждый файл провайдера:

```
# scrape.do
last_verified: 2026-08-18        # дата последней сверки с живыми доками
docs: https://scrape.do/documentation/

## Стабильные концепты (меняются редко)
- модель тарификации: кредиты за успешный запрос; что считается успешным
- ключевые параметры: render, super (residential), geoCode, customHeaders
- поведение при их 5xx: тарифицируется или нет ← КРИТИЧНО, сверять

## Протокол сверки
Перед генерацией кода: web_fetch страницы биллинга и параметров.
Если last_verified старше 60 дней — сверка обязательна даже без генерации.
```

`comparison.md` — таблица решения: markdown/структурная экстракция для LLM →
Firecrawl; максимальный success rate любой ценой → Bright Data Unlocker;
дёшево HTML с рендером → scrape.do; и колонка «что НЕ брать у провайдера»
(например, не платить за рендер, если сайт SSR).

`libs/blacklist.md`: `Anorov/cloudflare-scrape` — мёртв, обходил челлендж CF,
не существующий с ~2020; любые советы из старых статей про cfscrape/cloudscraper
проверять на дату.

## 9. Шаблоны

Каждый шаблон обязан содержать: triage, бюджеты, лог вердиктов, и **не
содержать** голых `retry(times=∞)` / `try/except: continue`.

- `python/cascade_single.py` — функция `fetch(url) -> Result`: L1 (curl_cffi)
  → triage → при BLOCKED L2 (Scrapling Stealthy) → triage → при BLOCKED L3
  (провайдер) → triage. Бюджет и учёт денег через budget.py.
- `python/scrapy_project/` — middleware `TriageMiddleware` (вердикты вместо
  стандартного RetryMiddleware, который ретраит 5xx вслепую — его отключить),
  `BudgetExtension`, экспорт метрик прогона.
- `python/scheduler_run.py` — фазы A–D из §6, очередь в SQLite, отчёт
  в ClickHouse/Telegram.
- `rust/l1_fetcher/` — rquest с Chrome-профилем, пул DC-прокси, semaphore
  на домен, порт triage-таблицы, вывод NDJSON.
- `rust/cascade/` — то же + fallback-вызовы scrape.do/Firecrawl по HTTP
  с тем же бюджетным счётчиком.

## 10. Definition of Done скилла

Скилл считается готовым, когда на тестовом наборе (3 сайта: SSR без защиты,
CSR-сайт, сайт за Cloudflare managed challenge):

1. probe.py правильно классифицирует все три
2. каскад достигает 100% живых URL, при этом сайт без защиты не сделал
   **ни одного** платного запроса
3. в очередь подмешаны 10 мёртвых URL — ни один не вызвал платный запрос,
   все в карантине после второго прогона
4. симуляция 502 (выключенный origin) — ретраи только бесплатные, URL
   закрыт в sweep следующего прогона
5. отчёт прогона содержит деньги по провайдерам и распределение вердиктов
6. месячный ретест-даунгрейд присутствует в scheduler как отдельная задача
```
